# deepseek-peak-guard — DeepSeek peak/off-peak cost guard

A DSH (DeepSeek Harness) plugin that decides whether a DeepSeek model call is
about to happen inside a **peak** or an **off-peak** billing window, and — in a
peak window — **asks the user to confirm before the request is dispatched**. It
also adds a row **above Settings in the Web GUI's left sidebar** carrying the
plugin name and an enable/disable switch.

> **On the two names.** The npm package and the client-module registration id are
> `dsh-peak-guard`, because a DSH client plugin's manifest name IS its
> module-table key — the browser resolves the bundle by that id. The repository
> and this page use the project name `deepseek-peak-guard`. The sidebar row shows
> the Chinese label `峰谷计费守卫`. All three refer to this one plugin; only the
> package id is load-bearing.

- **Interception point:** the `llm/stream` waterfall on `ctx.llm`, which covers
  *every* model call: the main conversation loop, subagents, compaction
  summaries, and session-title generation.
- **A refusal costs nothing:** the listener never calls `next()`, so the
  provider adapter is never constructed and no request is sent or billed.
- **Sidebar switch:** one click enables or disables the guard; the choice is
  persisted to disk and survives a restart.
- **No build step:** the host half is plain ESM JavaScript, and the browser half
  is generated by the ~150-line script that ships with the plugin — no monorepo
  toolchain required.

## The peak/off-peak rule (current, official)

From the footnote on the pricing page
([Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing), checked
2026-09-10):

> Off-peak rates are half of the peak rates. Peak hours are 01:00 - 04:00 and
> 06:00 - 10:00 UTC, Monday through Friday (all other hours are off-peak).

| Window | Beijing time | Price |
|---|---|---|
| **Peak** | Monday–Friday 09:00–12:00 and 14:00–18:00 | standard |
| **Off-peak** | every other hour, **plus all of Saturday and Sunday** | **50%** of standard |

> ⚠️ The older "daily 00:30–08:30 off-peak discount" was replaced by this
> peak/valley scheme on 2026-08-17, and weekends became wholly off-peak on
> 2026-08-23. An account still billed under the old rule can restore it with the
> `peakWindows` / `offPeakWindows` config shown below.

**One stated assumption:** DeepSeek does not document whether the bucket is
chosen by request start time, completion time, or invoice time. This plugin
classifies by **request start time** and says so in every prompt it renders.

## Install

A plugin module resolves `@deepseek-ai/*` from *its own* directory, so the
plugin is installed into the profile (linked to this checkout, or copied):

```powershell
cd F:\DSH峰谷插件

node install.mjs                 # link this checkout into the `web` profile
node install.mjs --copy          # copy the runtime files instead
node install.mjs --uninstall     # remove the row and the installed directory
node install.mjs --profile web --dsh-home D:\other-dsh
```

The installer edits only the profile's own `cordis.patch.yml`, and only inside
its own marker block, so unrelated user patches survive:

```yaml
# >>> dsh-peak-guard (managed by install.mjs) >>>
- insert:
    - id: peak-guard
      name: './dsh-peak-guard/index.js'
# <<< dsh-peak-guard <<<
```

Because the bundled `cordis.patch.yml` declares `dsh.bundle`, the package can
also be installed the standard way as a profile bundle:

```powershell
dsh plugin --profile web add F:\DSH峰谷插件
```

Trade-off: `dsh plugin add` is the distribution path, but pnpm installs it and
the layer joins on the **next start**; the junction keeps the patch row live
under the `web` profile's `patchReload: live`.

### ⚠️ The installed directory is a copy, and copies do not follow edits

This is the project's easiest trap, so read it first:

| Install | What the profile holds | After editing this checkout |
|---|---|---|
| `node install.mjs` (link) | a directory junction to this checkout | applies **automatically** |
| `node install.mjs --copy` | a **real copy** | does **not** apply — sync it |
| `dsh plugin add` | a pnpm-installed copy | does not apply |

In copy mode an edit here does not reach the profile, and the failure is
**silent**: the host half keeps running from the stale copy while the browser
half keeps serving the old bundle, which looks exactly like "my change did not
take effect". Sync it with:

```powershell
node sync.mjs          # report drift, then re-copy the runtime files
node sync.mjs --check  # report drift only; exits 1 when anything differs
```

A sync still needs a **page reload**: the browser bundle is content-addressed,
so a page picks a revision up when it loads (or through the client HMR channel).

> For development, prefer **link mode** (`node install.mjs` without `--copy`):
> `sync.mjs` then reports that the install is already a link, every edit is live,
> and only the page reload remains.

Verify with `dsh --profile web --dump-config | Select-String peak`, which should
show `- id: peak-guard` under the profile patch layer.

> ⚠️ **The browser half needs a page refresh.** The host half — including the
> sidebar switch's API route — applies as soon as the patch reloads, but
> `lib/client.js` is part of the page's boot manifest
> (`window.__DSH_BOOT__`), so after adding or changing the browser half, restart
> the dsh server and refresh the page. Run `npm run build:client` after editing
> `src/client.js`.

> ⚠️ If the install path contains non-ASCII characters (for example
> `F:\DSH峰谷插件`), create the junction **only with `install.mjs`**. Windows
> PowerShell 5.1 transcribes a junction target through the console code page,
> which yields a mojibake target path — still resolvable, but miserable to read
> and to debug.

## How it decides

```
model call → llm/stream waterfall
                └─ peak-guard classifies the provider/model
                     ├─ no match (other provider / model / auxiliary) → pass through
                     ├─ match inside an off-peak window → log (optionally notify) → pass through
                     └─ match inside a peak window → ask the user
                            ├─ approved → dispatch, and remember it for this window
                            └─ declined → terminal finish chunk, next() never called
```

A declined call yields `{ type: 'finish', reason: { kind: 'error', failure: {
code: 'PEAK_HOUR_DECLINED' } } }`. That code is deliberately outside
`dsh-llm-retry`'s default retryable set (`EMPTY_RESPONSE`, `RATE_LIMIT`,
`SERVER`, `TIMEOUT`, `TRANSPORT`), and the plugin remembers decisions, so a
provider configured with `retryPolicy.mode: 'always'` cannot turn a refusal into
a prompt loop.

### How often it asks

The default `askScope: 'window'` plus `suppressRepeatAsks: true` asks **once per
peak window**: approve a call in the morning window and the rest of that window
dispatches silently; the afternoon window (or the next day) asks again, and a
decline keeps refusing for the rest of its window. Set `askScope: 'call'` to ask
on every model call, or `suppressRepeatAsks: false` to disable remembering.

### The sidebar switch

**At the bottom of the Web GUI's left sidebar, above both the updater row and
Settings**, the plugin adds a `峰谷计费守卫` row: wide, it shows the name, the
live standing, and the switch; collapsed to the rail, a single status dot
(red = peak, green = off-peak, grey = disabled).

- Clicking toggles the guard. While disabled it does not intervene at all — every
  model call passes straight through.
- The choice is written to `.peak-guard-state.json` in the plugin directory and
  survives a restart; the config's `enabled` only seeds a switch that was never
  touched.
- The row reads and writes the host route `GET/POST /api/peak-guard/state` — the
  same channel the shipped updater panel uses. That route sits behind DSH's
  browser-session guard, so only your own browser can change it.
- The route mounts only once the `webServer` service is ACTIVE: `ctx.get()` is
  strict in cordis and answers `undefined` while the providing fiber is still
  pending, so the plugin waits with `ctx.inject(['webServer'], …)` instead of
  sampling it during `apply`. The outcome is recorded in
  `.peak-guard-state.json.boot.json` so "the sidebar cannot read the state" is
  diagnosable from outside the process.

> Layout note: the sidebar's footer action seat (`.footerActions`) is a
> horizontal flex row with **no wrap**, so every registrant is forced beside the
> others. The plugin injects one scoped stylesheet that makes that container
> wrap, gives its row the full line, and sets `order: -1` so the line comes
> first — above the updater row. The anchor matches the hashed class by its
> stable `footerActions` fragment; if a future DSH changes that hash the row
> degrades to sitting beside the updater row (still fully functional) rather than
> breaking the sidebar.

### Which channel asks

Tried in order, first available wins:

1. **`ctx.approval`** — only when the session's approval policy is `ask`. Under
   `never` the service answers `rejected` before any answerer runs, so the
   plugin skips it rather than burning a durable audit pair on a decision the
   user never made.
2. **`ctx.userQuestions`** — an independent interactive channel unaffected by
   the approval policy. This is why the confirmation still appears in a
   `danger-full-access` session, whose approval policy is pinned to `never`.
3. **Neither available** — `unaskableAction` decides: `proceed` (default) allows
   the call and injects an explicit notice into the conversation, or `block`
   refuses it.

Subagent calls are not asked about by default (`localAgentsOnly: true`):
subagents are ordinary agents on the same loop, and blocking them stalls
delegation, so they pass through with a log line.

## Configuration

Override the `peak-guard` row's `config` in the profile patch. A patch
**replaces** the whole `config` value rather than deep-merging it:

```yaml
- id: peak-guard
  name: './dsh-peak-guard/index.js'
  config:
    notifyOffPeak: true
    peakWindows:
      - start: '09:00'
        end: '12:00'
        weekdaysOnly: true
        label: morning peak
      - start: '14:00'
        end: '18:00'
        weekdaysOnly: true
        label: afternoon peak
    timeZone: 'Asia/Shanghai'
```

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `true` | Seed for the switch; once the sidebar has toggled it, the persisted value wins. |
| `providerPatterns` | `['deepseek-*']` | Provider routes to guard; globs. |
| `modelPatterns` | `['deepseek-*']` | Model ids to guard; globs. |
| `peakWindows` | Mon–Fri `09:00–12:00`, `14:00–18:00` | Peak list. `start` inclusive, `end` exclusive; `end` not after `start` wraps past midnight; `weekdaysOnly: true` leaves weekends off-peak. |
| `offPeakWindows` | `[]` | Explicit exceptions, consulted before `peakWindows` (public holidays, for example). |
| `timeZone` | `'Asia/Shanghai'` | IANA zone the windows are quoted in. |
| `requireConfirmation` | `true` | `false` warns without asking; peak calls pass through. |
| `gateAuxiliary` | `false` | Also gate session-title and compaction calls. |
| `notifyOffPeak` | `false` | Inject a conversation notice for off-peak calls too. |
| `unaskableAction` | `'proceed'` | No usable channel: `proceed` allows and notifies, `block` refuses. |
| `askTimeoutMs` | `0` | Confirmation budget in ms. **`0` waits until the user answers**, the request is cancelled, or the plugin is disposed; a positive value treats expiry as unanswered. |
| `suppressRepeatAsks` | `true` | Whether decisions are remembered at all. |
| `askScope` | `'window'` | `window` asks once per peak window (default); `call` asks on every model call. |
| `statePath` | `.peak-guard-state.json` beside the plugin | Where the sidebar switch is persisted. |
| `localAgentsOnly` | `true` | Ask only for root agents; let subagents through. |
| `showPrices` | `true` | Include the price comparison in the prompt. |
| `pricing` | see below | Presentation-only price table; it never affects classification. |

Shipped prices (CNY per million tokens, checked 2026-09-10): `deepseek-flash`
peak ¥2 in / ¥8 out, off-peak ¥1 / ¥4; `deepseek-v4-pro` peak ¥9 / ¥27,
off-peak ¥4.5 / ¥13.5, with cache-hit input quoted separately. DeepSeek reserves
the right to change its list, so the official page remains the billing truth.

To restore the retired 2025 rule (daily 00:30–08:30 off-peak), set
`peakWindows: []` and `offPeakWindows: [{ start: '00:30', end: '08:30' }]`.

## Tests

```powershell
npm test                          # node --test "tests/*.test.js"
npm run build:client              # regenerate lib/client.js after editing src/client.js
npm run build:client:check        # verify the committed artifact is current (CI; exits 1 when stale)
npm run sync                      # copy mode only: push changes into the installed copy
npm run sync:check                # report drift without writing
```

The artifact is **reproducible**: its build stamp is a content digest over
`src/client.js` and the build script, not a timestamp. Identical inputs produce
identical bytes, which is the precondition for `build:client:check` meaning
anything — under a timestamp, every rebuild would differ and no check could tell
a stale artifact from a fresh one.

72 deterministic, fully offline tests:

- `tests/peak.test.js` — timezone conversion, window boundaries (including
  wraparound and weekends), glob matching, price selection, every decision
  branch, and config validation.
- `tests/gate.test.js` — drives the real `llm/stream` listener through a fake
  Cordis context: pass-through, the approval channel, the user-questions channel
  (both answer shapes it has shipped), the refusal chunk, degradation with no
  channel, subagents, the decision memo, signal cancellation, disposal, and loud
  config errors.
- `tests/switch.test.js` — switch persistence and its tolerant reads, the
  `GET`/`POST`/`405`/`400` behaviour of `/api/peak-guard/state`, and proof that a
  disabled switch lets calls through untouched.
- `tests/client.test.js` — executes `lib/client.js` for real against the client
  module contract: the registration id, the exported surface, the slot it claims
  (the footer action above Settings), style injection, and rendering in both the
  wide and rail forms including the disabled and unreachable-host states.

## Known limits

- **The classification instant is an assumption** — request start time, because
  the provider does not document the rule.
- **Auxiliary calls are ungated by default** (`gateAuxiliary: true` changes it).
- **The price table will go stale**; it is presentation only.
- **Subagents are not asked by default** (see `localAgentsOnly`).
- **The confirmation panel is the shipped one**: the plugin reuses DSH's
  approval/question panel, so the panel title reads `llm.call` while the reason
  text carries the full detail (route, time, windows, prices).
- **The sidebar row is self-drawn**: it registers into the
  `sidebar.footer.action` seat (the row above Settings) rather than reusing a
  settings component, so it matches that row's neighbours without inheriting
  settings-page theming.
- **Code changes need a restart**; the patch row reloads live, but module reload
  is off in the shipped composition. Browser-half changes additionally need a
  page refresh, because the client bundle is part of the boot manifest.
